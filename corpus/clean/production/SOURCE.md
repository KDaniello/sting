# Source

Три продакшен-контракта, довендоренные 2026-08-05 ради **форм**, а не объёма: корпус не содержал ни одного примера тех идиом авторизации, на которых детекторы реально ошибаются.

## Зачем этот каталог существует

Три починки подряд, найденные на внешнем коде, оказались невидимы для `corpus/baseline.json`: `UR` и `UBM` в [фазе 4](../../../docs/phases_roadmap/phase-4-recursive-precision.md), `AC` в [фазе 5](../../../docs/phases_roadmap/phase-5-precision-floor.md). Замер по 47 файлам корпуса против 77 продакшен-файлов показал разрыв не в размере, а в составе:

| Форма | В корпусе было | В продакшене |
|---|---|---|
| обёртка `try` вокруг обработчика | **0%** | 18.2% |
| хелпер-метод на поле хранилища (`st.ownable.requireOwner`) | **0%** | 14.3% |
| делегирование библиотеке, возвращающей `bool` | **0%** | 13.0% |
| принадлежность по словарю, ключ — отправитель | **0%** | 6.5% |
| охрана ранним возвратом | 10.6% | 5.2% |
| экономическая авторизация | 17.0% | 7.8% |

Клонировано 2026-08-05.

## Чего вендорить нельзя — и это ограничило результат

Разрыв закрыт **не полностью**, и причина юридическая, а не техническая:

- **`webdom-market/webdom-contracts`** — **файла лицензии нет вовсе**, в `package.json` поле `license` отсутствует. То есть все права сохранены за автором, копировать нельзя. Это 13 из 14 источников формы `try` и **все 5** источников словарной принадлежности. Форма «принадлежность по словарю» остаётся в корпусе непокрытой.
- **`chainlink-ton/contracts/contracts/ccip` и `/mcms`** — **BUSL 1.1** до 12 марта 2029 (см. `LICENSE` репозитория: MIT распространяется только на содержимое *вне* этих каталогов). Из-за этого отпал `firedrill_entrypoint.tolk`, который импортирует `../ccip/router/types.tolk`.
- **`payment-channel-contract`** — файла лицензии нет.

Эти репозитории остаются источником для **прогона на месте**, как и раньше: в репозиторий попадает разбор находок, а не чужой код.

## Что изменено в вендоренном коде

Раскрывается полностью, потому что это правка чужого исходника:

1. **Пути импортов уплощены.** Корпусный проект — плоская директория (`discover_merged_projects` читает только прямых детей), поэтому `import "../lib/utils.tolk"` → `import "utils.tolk"`, `import "@contracts/fees"` → `import "fees.tolk"`. Затронуто 16 файлов. Импорты `@stdlib/*` не тронуты.
2. **Удалён `nominator-v2/contracts/Elector.types.tolk`** — единственный его импорт (`@tests/elector-utils`) указывает в невендоренную тестовую инфраструктуру, а сам файл не импортируется ни одним другим. Оставлять файл с висящим импортом хуже, чем не брать его.

Содержимое функций не менялось нигде.

## Проверка компиляции

Отдельная компиляция каждого энтрипоинта **не проводилась**: `chainlink-ton` собирается своим тулчейном с генерацией кодовых ячеек, `nominator-v2` — через Acton с отображениями путей `@contracts/*`, которые здесь как раз уплощены. Ставить оба тулчейна ради проверки трёх проектов сочтено несоразмерным.

Что это значит для измерения: `sting-bench` сливает файлы проекта **текстом** и анализирует результат через `lint_source`, который никогда не подключает проектный контекст компилятора (см. док-комментарий `LintController::lint_source`). То есть разрешимость импортов на числа бенча не влияет вообще. Но заявлять «компилируется» без проверки было бы неправдой, поэтому здесь стоит «не проверено», а не молчание.

## Что это изменило в числах

`AC` — 51.4% → **51.1%** при росте ложных с 32 до 45: новые формы дали 3 ложных срабатывания в `chainlink-ownable-counter`, ровно те две идиомы, которые фаза 5 назвала пробелами распознавания. `LEP` +3, `UBM` +1 — на реальном коде, не на инъекциях. Агрегат 84.6% → **83.3%**, набор по умолчанию **96.5%**.

Числа стали хуже, и это и есть результат: они были лучше ровно потому, что корпус не содержал трудных форм.
