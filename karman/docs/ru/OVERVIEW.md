# Обзор — машина от начала до конца

Karman отвечает на один вопрос о криптоэкономическом дизайне: **что этот механизм делает под
худшим правдоподобным давлением?** Этот документ проходит машину один раз, простым языком.
Правила и границы, которые он упоминает, точно сформулированы в
[`ARCHITECTURE.md`](./ARCHITECTURE.md); что делает ответы заслуживающими доверия —
[`VERIFICATION.md`](./VERIFICATION.md).

## 1. Части

Симуляция — это четыре вещи:

- **Механизм** — правила площадки: лендинг-рынок с порогами ликвидации, книга перпетуальных
  фьючерсов с маржой и funding, кривая AMM. В коде это детерминированный конечный автомат:
  состояние на входе, действие на входе, события на выходе. Без случайности, без часов, без
  float.
- **Агенты** — популяция, действующая на механизм: ликвидаторы, арбитражёры, шумовой поток,
  киты с графиками вестинга. Случайность живёт в агентах, и каждый бросок берётся из
  сидированного потока.
- **Движок** — цикл, дающий каждому агенту его ход, применяющий действия к механизму и
  продвигающий логическое время. Он generic над механизмом: один движок гоняет каждое
  семейство, и именно это конкретно означает «универсальное ядро».
- **Данные** — реальное состояние, с которого стартует прогон, и реальные пути, которые он
  реплеит: резервы из API протокола, серия оракульных цен, записанный эпизод ликвидаций. Всё
  входит через один крейт, пишется на диск фикстурой, и прогон читает фикстуру — прогон никогда
  не ходит в сеть.

## 2. Один прогон

Прогон — чистая функция. Входы — файл сценария (какой механизм, какие параметры, какие агенты)
и 64-битное зерно. Движок тикает: на каждом тике каждый агент смотрит на состояние и может
действовать, механизм применяет каждое действие или отклоняет его, затем срабатывают правила
времени — начисляются проценты, рассчитывается funding, разлочиваются токены. После каждого
перехода проверяются собственные инварианты механизма; нарушение громко обрывает прогон,
потому что оно означает ошибку в реализации механизма, а это никогда не должно выглядеть
рыночным исходом.

Тот же сценарий, то же зерно: побитово одинаковый результат на любой машине. Это не приятная
мелочь — это то, что делает находку воспроизводимой, баг — сообщаемым по зерну, а свип —
возобновляемым.

## 3. Свипы

Один прогон — анекдот. Режимы движка превращают прогоны в свидетельства:

- **Монте-Карло** — тысячи независимых прогонов от одного зерна сценария, каждый
  воспроизводим отдельно по своему номеру. Выход — распределение, а не история.
- **Реплей** — записанная реальность, прогнанная через механизм, для валидации
  ([`VERIFICATION.md`](./VERIFICATION.md), уровень 1).
- **Адверсариальный поиск** — режим, ради которого проект существует: поиск по пространству
  сценариев ценового пути, поведения агентов, параметрического угла, который ломает дизайн.
  Выход — худший правдоподобный случай, а не средний.

## 4. Три семейства

Ядро доказывает универсальность реализацией трёх семейств механизмов, которые назначают цену
тремя несвязанными способами:

| Семейство | Цена приходит из | Трудная часть |
|---|---|---|
| лендинг (кредит) | снаружи — оракул | каскады ликвидаций, bad debt |
| перпетуальные фьючерсы | изнутри — книга ордеров | маржа, funding, принудительный делеверидж |
| кривые (AMM, bonding) | формула над резервами | осушение, зависимость от пути |

Всё, что движку нужно специфично для одного семейства, — провал дизайна; семейства — равные
реализации одного порта. Большинство остальных крипто-механизмов — комбинации этих трёх:
стейблкоин — кредит плюс кривая, лаунчпад — кривая плюс вестинг, — поэтому эти три первые.

## 5. Доверие

Симулятор легко построить и легко ему не верить. Хребет проекта — четырёхуровневая лестница
верификации: точная арифметика против эталонной реализации, реплей реальных эпизодов,
статистическая реалистичность, пререгистрированное предсказание — и текущий уровень механизма
является частью его публичного API. Лестница с критериями прохождения —
[`VERIFICATION.md`](./VERIFICATION.md).

## 6. Поверхности

Движок — прежде всего библиотека. `sting-karman-cli` — эталонная поверхность: она загружает
сценарий, втыкает конкретные механизмы и агентов в порты ядра — единственное место, где
происходит соединение, — и печатает измеримый вывод. SDK в `sdk/` открывает тот же контракт
сценария в Python; файл сценария означает одно и то же на каждой поверхности.
