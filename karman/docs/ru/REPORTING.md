# Отчётность — что каждый прогон обязан сказать о себе

Свип, напечатавший число, не закончен: число без контекста — мнение. Каждый свип издаёт отчёт
прогона, и отчёт судится одним стандартом — **он отвечает на вопросы читателя без автора в
комнате**. Этот документ фиксирует, что для этого требуется. Исполняемая половина живёт в
`sting-karman-report`; композиционные корни обязаны производить отчёт для каждого свипа, а не имеют
такую опцию.

## 1. Почему это контракт, а не фича

Отчётность — часть системы, которую откладывают чаще всего, и отложенность невидима до первого
жёсткого вопроса — *сколько прогонов реально завершилось? какие данные исключены? могу ли я
воспроизвести это число?* — на который нет ответа. К тому моменту прогоны уже потеряны.
Поэтому отчёт производится во время прогона, из самого прогона, и свип, в отчёте которого нет
обязательной секции, — проваленный свип, а не лаконичный.

## 2. Обязательные секции

Каждый отчёт несёт все девять. Секция, которой нечего сказать, говорит это явно — «ни один
прогон не оборвался» — это информация; отсутствующая секция — вопрос, на который потом никто
не ответит.

1. **Идентичность.** Имя сценария, зерно, количество прогонов и тиков, и точная команда,
   воспроизводящая свип. Отчёт, чьи числа нельзя воспроизвести, — мнение.
2. **Начальные условия.** Состояние, с которого свип стартовал, — резервы, популяция,
   механизм, — чтобы у каждого дрейфа в отчёте была видимая база.
3. **Покрытие.** Запланированные против завершённых против оборванных прогонов, с причиной
   первого обрыва дословно. Потери называются, а не сальдируются: свип, тихо потерявший треть
   прогонов, измерил другую реальность, чем сообщает.
4. **Исходы.** Чего свип достиг — счётом, а не распределением, — и чего не достиг ни разу.
   Распределение отвечает на вопрос «сколько»; только счёт отвечает на вопрос «случилось ли», а
   на второй ни один отдельный прогон ответить не может. Реже одного прогона из десяти это
   заявляется счётом и никогда долей: читатель, которому вручили «0,03%», уносит ожидание, а
   читатель, которому вручили «три прогона из десяти тысяч», уносит три прогона.
5. **Распределения.** Для каждой метрики: её база, где она есть, медиана с дрейфом от базы и
   перцентильный коридор (min · p05 · p25 · медиана · p75 · p95 · max) с относительной шириной
   коридора, разброс вокруг среднего и единицу минус этот разброс к медиане — методом
   nearest-rank над целыми, точно и независимо от платформы. Точечные
   оценки без коридоров запрещены: медиана без разброса прячет ровно ту информацию, ради
   которой риск-инструмент существует. Активность — тоже метрика: применённые и отклонённые
   действия — распределения, а не сноски.
6. **По режимам.** Там, где свип был смесью будущих, каждое из них подводится отдельно — свой
   коридор, свой разброс, своя стабильность, — потому что смесь, схлопнутая в одно
   распределение, сообщает среднее по будущим, которые вместе не случаются никогда. Часть, где
   прогонов слишком мало, чтобы нижний край коридора был чем-то кроме минимума, заявляет свою
   середину и никакого коридора, вместо того чтобы печатать экстремумы под именами перцентилей.
7. **Экстремальные прогоны.** Для каждой ключевой метрики — номер прогона с наименьшим и
   наибольшим финальным значением. Номер прогона — это поток RNG, поэтому каждый экстремум
   воспроизводим точно: отчёт вручает читателю худший случай, а не только его существование.
8. **Вердикт.** Заявка, против которой оценивался свип, процитированная вместе с датой
   регистрации, основанием и зонами, рядом с измерением, которое её решило. Свип, против
   которого ничего не зарегистрировано, говорит именно это, потому что «нет вердикта» — это
   находка, а молчащая секция — нет.
9. **Пробелы — на что этот прогон не может ответить.** Неподключённые слои, некалиброванные
   популяции, несчитанные явления, исключённые данные — каждый со своим следствием. Эту секцию
   заполняет композиционный корень, потому что только он знает, что он подключил и что
   оставил снаружи. Пустой список пробелов — заявление о полноте, и оно почти всегда ложно.

## 3. Правила

- **Отчёт — артефакт.** Пишется на диск с crash-safe дисциплиной `sting-karman-data`, в Markdown
  для читателя и доступен как JSON для машин. Консольная сводка называет путь отчёта.
- **Вердикты только против пререгистрированных порогов.** Отчёт может утверждать вердикт
  («подтверждено», «опровергнуто», «без вердикта») только когда пороги зафиксированы до
  прогона — дисциплина `findings/` (docs/VERIFICATION.md §4). Порог, придуманный после
  взгляда на распределение, — не вердикт, как бы он ни назывался.
- **Консервативность называется, а не подразумевается.** Там, где сообщённое число несёт
  известное смещение, отчёт называет направление (docs/VERIFICATION.md §5).
- **Пробелы растут прежде, чем сокращаются.** Закрыть пробел — значит поставить слой, который
  его закрывает; удалить строку пробела, ничего не поставив, — фальсификация записи.

## 4. Где живёт отчётность

| Часть | Дом | Ответственность |
|---|---|---|
| `RunReport`, `MetricSummary`, `Coverage`, `Identity` | `sting-karman-report` | структура и её Markdown-рендер; чистые значения, без I/O |
| запись артефакта | `sting-karman-data::write_text_artifact` | crash-safe вывод в файл |
| заполнение секции пробелов | композиционные корни (`sting-karman-cli`, SDK) | называние того, что подключено и что нет |
| пороги вердиктов | `findings/` | пререгистрированы, неизменяемы после регистрации; JSON, чтобы отчёт оценивал себя против них, а не читатель сверял глазами |
| оценка свипа против заявки | `sting-karman-report::grade` | отказывается оценивать свип, против которого заявка не регистрировалась; цитирует зоны в отчёт рядом с исходом |
