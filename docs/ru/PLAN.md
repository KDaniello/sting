# План

План — не список желаний и не трекер сессии. Это последовательность работ, каждая из которых
закрывается гейтом, а каждый гейт имеет условие провала. Работа без условия провала в план не
входит.

Порядок работ задан один раз и обжалованию внутри плана не подлежит: **документация получает
дисциплину → ядро догоняет цепь → код вливается в одно дерево → способности описываются →
продукты выводятся из описи**. Дисциплина идёт первой, потому что три следующих гейта пишут свои
числа в эти же документы. Обратный порядок остального означает, что опись описывает четыре
репозитория вместо одной платформы, а продукт выбирается по памяти автора, а не по тому, что
платформа умеет.

### 0.3. Три расхождения, из которых выведен план

**Ядро видело язык января, когда язык жил в июле.** Грамматика `tree-sitter-tolk` 0.0.5
опубликована 2026-01-17, вендорный `tolk` собран 2026-07-15, и из-за этого 54 файла корпуса из 297
несли узел ошибки. Закрыто на M1: грамматика вендорена и пропатчена, разбираются все 297, а
компилятор не читает ничего, что она отвергает.

**Непарсинг молчал.** `sting lint` на файле с `ERROR`-узлами отдавал `"results": []` и код возврата
0 — ровно то же, что на чистом файле. Анализатор, отвечающий одинаково на «дефектов нет» и «файл не
понят», не анализатор. Закрыто на M1: позиция названа, прогон выходит с ненулевым кодом.

**Проекты положены рядом, а не влиты.** Четыре workspace, четыре имени в `exclude`, пять путей к
одним данным цепи, три несовместимых режима линта. Прежняя редакция ставила публикацию датасета
впереди вливания — то есть предлагала выложить наружу артефакт раньше, чем сказано, чем он
отличается от каталога фонда.

## 1. Гейт О — ядро видит живой TON

### 1.1. Чего ядро не видит

| Конструкция | Версия языка | Разбирается |
|---|---|---|
| `int[]`, динамические массивы | 1.3 | нет |
| `??` | 1.3 | нет |
| `@abi.clientType(...)` и прочие точечные аннотации | 1.4 | нет |
| `contract Name { storage: … }` | 1.0 и далее | нет, весь блок — один `ERROR` |
| лямбда `(x: int) => x + 1` | 1.2 | нет |
| `string` и `StringBuilder` | 1.3 | да |
| `enum` | 1.1 | да |
| `map<K, V>` | 1.1 | да |
| `lisp_list<T>` | 1.3 | да |
| `address` отдельным типом | 1.2 | да |
| `lazy` | 1.0 | да |
| объединение `int` с `null` | 1.2 | да |

Пять из двенадцати. Хуже пропорции то, что `contract { }` — именно та конструкция, из которой
компилятор строит ABI: слепота приходится на смысловой центр языка, а не на его край.

### 1.2. Работы

**О1. Непарсинг перестаёт быть тишиной.** `sting lint` на дереве с `ERROR`- или `MISSING`-узлами
возвращает диагностику с позицией и ненулевой код возврата. Правило формулируется запретом: файл,
который не разобран, не имеет права выглядеть файлом без находок.

**О2. Слепота получает число.** Доля файлов корпуса без `ERROR`-узлов — сейчас 100%, на момент написания 81.8% — считается
скриптом и попадает в CI. Падение доли — красный CI.

**О3. Компилятор становится оракулом.** Вендорный `tolk` 1.4.2 прогоняется по корпусу; файл,
который компилятор принял, а грамматика не разобрала, — расхождение, и оно перечислено поимённо.
Список расхождений либо пуст, либо объяснён построчно; третьего состояния нет.

**О4. Конструкции закрываются, и называет их оракул.** Порядок задан ценой слепоты. Этот документ
назвал пять по changelog и в трёх ошибся — ровно то, чего стоит догадка против оракула: `??`
разбирался и раньше, а ни динамические массивы, ни названная здесь форма лямбды синтаксисом Tolk не
являются. Способ — правки в грамматику вверх по течению, а не второй текстовый обходной путь:
`extract_contract_headers` существует заплатой и удаляется тем же коммитом, которым грамматика
получает правило.

**О5. Глобальная версия называется.** Эмуляция фиксирует global version явно, версия
`libemulator` читается на старте и сверяется с ожидаемой. Прогон на неизвестной версии
отказывается работать, а не работает молча.

**О6. Семантика gv12–gv15 разбирается против детекторов.** По каждому из 14 сказано, меняет ли
его изменение цепи. Три пересмотра назначены заранее: UBM против формата bounce из gv12, проверки
отправки против `SENDMSG` из gv14, работа с библиотеками против запрета из gv15.

**О7. Периметр языков объявляется.** Tolk — живой и получает всю глубину. FunC — legacy языка, но
не цепи: mainnet им забит, поэтому экстрактор и грамматика остаются ради словаря и декодирования.
Tact — заморожен на компиляторе 1.6.13: тесты идут, развития нет. Замер шёл первым, а заморозка
следует за ним — **от 1.5% до 3.3% из 389 уникальных хешей кода mainnet объявляют себя Tact**,
что есть пол, а не потолок, ибо маркеры необязательны ([`domains/method-dictionary.md`](./domains/method-dictionary.md) §8).

### 1.3. Гейт О

Ядро догнало цепь, когда одновременно верно всё нижеследующее. **Всё шесть верно, и гейт пройден.**

| Условие | Сегодня |
|---|---|
| ни один файл не разбирается с ошибкой молча: есть диагностика и ненулевой код возврата | `sting lint` называет позицию и отказывает |
| доля разбираемого корпуса считается командой и проверяется гейтом | 297 из 297, пол в 100% внутри `make pr` |
| расхождений «компилятор принял, грамматика не приняла» нет либо каждое названо | оракул идёт в обе стороны, 0 в каждой |
| разбирается каждая конструкция, которую называет оракул, текстовая заплата удалена | `extract_contract_headers` ушёл вместе с тестами |
| глобальная версия и версия эмулятора зафиксированы и проверяются на старте | версия 14 и коммит `3f598aa2`, отказ на каждом пути конфига |
| по каждому из 14 детекторов сказано, что с ним делают gv12–gv15 | 14 строк, `UBM` сдвинулся дважды |

**Условие провала:** хотя бы один файл корпуса разбирается с ошибкой, и пользователь об этом не
узнаёт. Тогда гейт не пройден, сколько бы конструкций ни добавила грамматика.

### 1.4. Чего гейт О не делает

Он не добавляет ни одного детектора и ни одного пользователя. Он возвращает уже написанным
детекторам право говорить о файле, прочтённом целиком. Числа точности, замеренные до гейта О,
после него пересчитываются: 96.4% precision получены на корпусе, 18.2% которого анализатор не
видел.

## 2. Гейт В — вливается код, а не папки

### 2.1. Принцип

Вливание — не перенос каталога в общее дерево, а сведение общего кода к одному экземпляру.
Проект, лежащий в подкаталоге и собирающийся отдельным workspace, положен рядом, а не влит.
Обратный критерий: если после вливания в репозитории осталось две реализации одного и того же —
вливание не состоялось.

### 2.2. Пять путей к одним данным

| Где | Чем | Что умеет |
|---|---|---|
| `crates/sting-corpus`, `sting-abi-*` | `ureq`, синхронно, плюс `libemulator` | code+data по адресу, вызов get-методов |
| `karman/crates/sting-karman-data` | toncenter v3 и tonapi | перепись коллекций, пагинация, ретраи |
| `sybil/crates/ingestion` | toncenter, ClickHouse, `tokio` | поток транзакций, follower |
| `tools/ton-res` | pytoniq, лайтсервер | доказанное состояние по `last_transaction_lt` |

Пять путей, пять наборов ретраев, пять моделей адреса. Это и есть предмет вливания; остальное
вторично.

### 2.3. Чем вливание дороже, чем кажется

Прежняя редакция считала вливание переносом крейтов. Перенос — меньшая его часть.

**Пины расходятся, и расхождение содержательное.**

| Зависимость | `sting` | `karman` | `sybil` |
|---|---|---|---|
| `thiserror` | 2 | **1** | 2 |
| `toml` | 1.1 | **0.8** | — |
| HTTP | `sting-chain` | через него | через него |
| Генератор | — | `rand_chacha` 0.3, `rand_core` 0.6 | — |
| `pyo3` | — | 0.29, `abi3-py39` | 0.29 |
| Постороннее | — | **`revm` 42, `alloy-sol-types` 1** | `arrow`/`parquet` 59, `clickhouse` 0.15 |

Разные поколения `rand` — это разная семантика seed, то есть разный детерминизм. Для проекта, у
которого воспроизводимость по seed вынесена в дисциплину, это не деталь сборки.

**Режимы линта несовместимы.** Корень объявляет `unsafe_code = "forbid"` и `deny` на
`unwrap`/`expect`/`panic`. У `karman` пять блоков `unsafe` в `sting-karman-cli/src/alloc.rs` — считающий
аллокатор; у `sybil` таких запретов нет вовсе. `forbid` не снимается локальным `allow`: либо
крейт не наследует общие линты и это записано поимённо с причиной, либо меняется код.

**Периметр расширяется молча.** `karman` тянет в TON-workspace исполнитель EVM. Либо он объявлен
частью платформы, либо остаётся за периметром вместе со своим крейтом.

### 2.4. Работы

| Шаг | Что | Гейт |
|---|---|---|
| В1 | `sting-chain`: один доступ к цепи, синхронное ядро, асинхронный адаптер поверх для `sybil` | приёмник `sybil` воспроизводит снимок из `tests/snapshots`, перепись `karman` воспроизводится байт в байт |
| В2 | `sting-address`: одна модель адреса из `sting-core` и `sybil/common` | compile-fail тест «владелец против jetton-кошелька» проходит из общего крейта |
| В3 | `sybil/graph/decode.rs` заменяется вызовом `sting-abi-core` | граф на том же входе даёт тот же набор рёбер |
| В4 | Реконсиляция пинов по таблице §2.3, включая поколение `rand` | прогоны по seed до и после дают тот же вердикт либо расхождение объяснено |
| В5 | Один режим линта: каждый влитый крейт наследует `[lints] workspace = true`, исключения перечислены поимённо | `cargo clippy --workspace` зелёный без правок `allow` по ходу |
| В6 | `sting-karman-core` получает исполнитель TVM через `sting-emulator` | механизм с реальным контрактом прогоняется дважды по одному seed с одинаковым результатом |
| В7 | Правило подлинности переписи переезжает в `sting-scamcheck` | копии воспроизводятся из нового места офлайн: 40 за 7 оспариваемыми именами на 167 коллекций |
| В8 | `exclude` снимается, `tonomics` закрывается дубликатом `karman` | `cargo test --workspace` собирает и прогоняет 902 + 439 + 136 одной командой |

`tonomics` начат раньше `karman` и стоит; `karman` живой. Из `tonomics` забирается веха M6 и
`DIAGNOSTICS.md` — «где движок ошибается и почему», — после чего каталог удаляется с диска, а
история остаётся в git. Условие провала этого шага: если в `karman` не оказалось ни одной строки,
взятой из `tonomics`, забирать было нечего и удалять надо было сразу.

`tools/ton-res` не переписывается на Rust и крейтом не становится. Это измерительный прибор: он
отвечает, расходится ли источник данных с цепью, и уже ответил «нет» цифрой 0.00% на 160 объектах.
Прибор запускается несколько раз в год, его ценность — в доказанном состоянии через лайтсервер, а
не в скорости.

### 2.5. Целевой граф

После вливания дерево состоит из пяти слоёв, и зависимость направлена только вниз.

```
Слой 5  продукты      sting-abi-service · sybil-realtime-api · sting-karman-cli · sting-cli
Слой 4  предметные    sting-detectors · sting-scamcheck · sybil-cluster · karman-mech-*
Слой 3  анализ        sting-semantic · sting-dataflow · sybil-features · sting-karman-core
Слой 2  разбор        sting-abi-core · sting-ast · sybil-graph
Слой 1  фундамент     sting-core · sting-address · sting-chain · sting-emulator
```

**Инвариант.** Крейт слоя N зависит только от слоёв ниже N. Обратная зависимость является
архитектурной ошибкой и не проходит ревью.

### 2.6. Гейт В

Вливание состоялось, когда одновременно:

- доступ к цепи существует в одном экземпляре, четыре остальных удалены;
- модель адреса одна, compile-fail тест живёт в общем крейте;
- пины сведены, поколение генератора одно, расхождение вердиктов по seed отсутствует либо
  объяснено;
- режим линта один, исключения перечислены поимённо с причиной;
- `exclude` пуст, `cargo test --workspace` прогоняет всё одной командой.

**Условие провала:** в репозитории осталось две реализации доступа к цепи. Тогда гейт не пройден,
сколько бы крейтов ни переехало.

### 2.7. Чего гейт В не делает

Он не объединяет дисциплину прогонов. `findings/` в `karman` остаётся отдельным каталогом со своим
форматом: это реестр утверждений, а не код. Он также не сводит `bohr`, `laplace` и `pauli` с этим
репозиторием — их роднит дисциплина, а не код, и общая библиотека такой дисциплины оказалась бы
тонким слоем над `rand` с seed.

## 3. Гейт И — опись возможностей, API и выходов

### 3.1. Что считается способностью

Способность — не функция, не крейт и не строка в README. Это пара «вход → выход», которая
воспроизводится одной командой из чистого клона и подтверждена числом. Способность без команды —
намерение; способность без числа — обещание.

Опись отвечает на вопрос, у которого сегодня нет ответа ни в одном документе: **что платформа
умеет целиком**. `docs/API.md` описывает три бинаря контура `sting`; `karman` и `sybil` в нём не
существуют вовсе.

### 3.2. Форма записи

Каждая способность получает строку в `CAPABILITIES.md` с восемью полями:

| Поле | Что в нём |
|---|---|
| Идентификатор | стабильный, ссылки на него не переписываются |
| Вход | тип и происхождение: исходник, адрес, хеш, список адресов, конфигурация |
| Выход | схема и её версия: SARIF 2.1.0, `ContractSchema`, JSON-датасет, отчёт прогона |
| Команда | одна строка, воспроизводимая из чистого клона |
| Число | что замерено и на чём: покрытие, precision, latency, доля |
| Стоимость | сеть или локально, порядок времени, нужен ли `libemulator`, ClickHouse, ключ API |
| Ограничение | чего способность не делает — отдельным полем, а не оговоркой |
| Слой | из §2.5, для проверки инварианта |

### 3.3. Что подлежит описи

| Контур | Ожидаемых способностей | Чем подтверждается сегодня |
|---|---|---|
| security | статический разбор, 14 детекторов, динамическая проверка через эмулятор, бенчмарк, фаззинг | `docs/API.md` §2, `corpus/baseline.json` |
| abi-layer | извлечение схемы из трёх языков, словарь method id, распознавание без исходников, HTTP-поверхность, покрытие | `docs/API.md` §3–4 |
| scamcheck | 11 сигналов, композитный скоринг, подлинность коллекций | `docs/API.md` §5 |
| sybil | приём из цепи, граф финансирования, фичи, кластеризация, скоринг, реалтайм | описи нет |
| karman | движок, агенты, пять механизмов, сценарии, отчёты, перепись рынка | описи нет |
| приборы | `ton-res`: расхождение источника с цепью | описи нет |

### 3.4. Гейт И

Опись готова, когда одновременно:

- каждая способность имеет строку со всеми восемью полями;
- каждая команда из описи запускается на чистом клоне и даёт заявленный выход;
- каждый выход имеет схему с версией;
- у каждой способности заполнено поле «чего не делает»;
- ни одна способность не нарушает инвариант слоёв.

**Условие провала:** способность описана, но её команда не воспроизводится. Тогда гейт не пройден,
сколько бы строк ни было в таблице.

### 3.5. Чего опись не делает

Она не делает способность нужной. Опись отвечает «что умеем», продукт отвечает «кто за это
платит», и второе из первого не следует. Опись нужна ровно затем, чтобы выбор продукта опирался на
перечень, а не на память.

## 4. Продукты

### 4.1. Что здесь считается продуктом

Продукт — не контур, не крейт и не способность. Это пара «кто платит» и «за что», у которой
названы готовность, недостающее и мерило успеха.

Способность опознавать контракт по хешу кода с покрытием 86.2% mainnet — не продукт. Продуктом её
делает покупатель, которому нужен ответ «что это за контракт», и цена, которую он за ответ платит.

### 4.3. Описания

#### П1. Sybil / anti-farm API

**Что.** Приём: список адресов. Ответ: какие из них принадлежат одному человеку, с оценкой
уверенности и объяснением — через какой узел финансирования они связаны.

**Почему покупатель есть.** Экосистема выросла на tap-to-earn, каждая раздача съедается
фермерами, и у раздающего нет способа отличить сто человек от одного человека со ста кошельками.
Ветер в спину: в июле 2026 объявлен некастодиальный кошелёк Gram во всех клиентах Telegram — число
кошельков на человека растёт быстрее, чем число людей.

**Что построено.** 8 крейтов, 9 481 строка Rust и 36 файлов Python, 136 собственных тестов зелёные: приём из
цепи, граф финансирования, фичи, кластеризация, скоринг, реалтайм-эндпоинт, ground truth из
песочницы.

**Чего нет.** Развёрнутого ClickHouse, калибровки на живых метках, упаковки, цены. 18 тестов
приёмки не запускаются без базы — это не «пропущенные тесты», а незамеренный контур.

**Чем меряется.** Precision и recall на ретро-кампании с известным исходом. Порог называется до
прогона.

**Чего продукт не делает.** Не доказывает, что кластер принадлежит одному лицу. Он показывает
координацию. Разница юридическая и существенная: координация — наблюдаемое свойство графа,
принадлежность — утверждение о людях, которое граф не подтверждает.

#### П2. Словарь method id и decode API

**Что.** Два выхода. Первый — открытый датасет соответствий method id ↔ имя. Второй — платный
ответ на хеш: что произошло, словами и полями.

**Против чего.** Прежняя редакция утверждала, что аналога `4byte.directory` в TON нет. Каталог
фонда `ton-blockchain/abis` на 2026-08-21 несёт 283 контракта, 332 хеша кода, 1 299 префиксов
опкодов и 600 имён get-методов. Утверждение «аналога нет» из плана уходит; вместо него — различие
природы, а не размера: их артефакт отвечает «мы описали важные контракты», наш — «мы знаем, что
такое почти всё, что реально задеплоено», 86.2% уникальных кодов mainnet, 337 из 391. Курирование
руками не догоняет обход, но и обход не описывает контракт лучше его автора.

**Что построено.** 1 388 method id машинного происхождения, у каждой записи — где она встречена.
Извлечение ABI из Tolk через родной `abi.json` компилятора 1.4, из Tact и FunC — своими
экстракторами. `dictionary-probe`, распознающий контракты без исходников вызовом get-методов на
реальном состоянии.

**Что измерено против этого продукта.** `ton-res` сравнил три публичных индексатора с цепью на 160
объектах: расхождений по значениям 0.00% у всех трёх. Питч «у индексаторов плохие данные»
опровергнут собственным замером. Продавать надо смысл: ни цепь, ни индексатор не отвечают на
вопрос «что это была за операция».

**Чем меряется.** Доля запросов, на которые API отвечает разбором, а не `Unknown`. Порог — доля
покрытия mainnet, то есть 86.2% на старте.

**Чего продукт не делает.** Не верифицирует исходник. Соответствие «хеш кода → имя операции» —
утверждение о байтах, а не о том, что автор контракта имел в виду.

#### П3. Скам-скоринг для кошельков

**Что.** Метка риска рядом с жетоном, подарком или адресом: ловушка на продажу, право допечатки,
концентрация у владельца, поддельная коллекция, тайпсквот домена.

**Что построено.** 11 сигналов. Тайпсквот распознаётся на реальном примере: `fragm-ent.com` против
`fragment.com`, расстояние 1, коллекция Durov's Caps.

**Чего нет.** Размеченного набора скамов и ни одной интеграции.

**Особенность.** Это OEM-продажа двум-трём покупателям, а не самостоятельный сервис. Первая
интеграция тянет остальные: кошелёк без такой метки начинает выглядеть хуже соседа.

**Чего продукт не делает.** Не выносит приговор. Он выдаёт сигналы и их основания; решение
показывать предупреждение остаётся за кошельком.

#### П4. Оценка и оракул рынка подарков

**Что.** Цена подарка по сделкам всех площадок, фильтр отмывочных сделок, индекс коллекции,
проверка подлинности, оценка залога.

**Что построено.** Перепись рынка: 1 295 768 предметов, 117 коллекций. Правило подлинности: 27
подделок на 167 коллекций. Реальный оборот измерен — сделками являются 11.7% переходов, остальные
считают оборот в восемь раз больше, чем он есть.

**Чего нет.** Агрегации сделок по площадкам: она вне цепи, во внутренних балансах.

**Конкурент.** Gift Asset — 28+ проектов, 650 млн точек данных. Ниша занята всерьёз.

**Чем меряется.** Отклонение оценки от следующей реальной сделки. Порог называется до замера.

#### П5. Комплаенс и AML

**Что.** Скоринг адресов, происхождение средств, кластеры, Travel Rule.

**Что построено.** Три входа, которые нужны такому продукту, есть все три: декодирование (П2),
кластеризация (П1), сигналы риска (П3).

**Чего нет.** Юридической стороны, знания требований, корпоративных продаж. Это трек, который не
закрывается кодом.

**Чем меряется.** Первый подписанный VASP. Промежуточных метрик у этого продукта нет.

#### П6. Публичный бенчмарк безопасности

**Что.** Открытая методика и корпус, на которых измеряется точность любого анализатора TON,
включая чужие.

**Против чего.** С 8 мая 2026 официальный тулчейн Acton ставится вместе с проектом и несёт 39
правил линта, из которых E007 `no-bounce-handler`, E013 `unauthorized-access` и E018
`random-requires-initialization` покрывают ту же землю, что UBM, AC и EPS. Вопрос «зачем
разработчику второй линтер» получил ответ раньше, чем мы на него ответили: незачем.

**Куда уходит контур.** Туда, где линтер пуст по устройству, а не по недосмотру: межфайловый
taint, динамическая проверка на реальном состоянии через `libemulator`, семантика глобальных
версий цепи. Линтер разбирает исходник; он не эмулирует транзакцию и не знает, что gv15 сделал с
библиотеками.

**Что публикуется вместе с хорошими числами.** Плохие: AC — 32.8% precision, LEP — 32.6%.
Бенчмарк, публикующий только удачные детекторы, мерилом не является. У линтера Acton и у Misti —
42 детектора, только Tact — опубликованных цифр точности ноль; держащий мерило не конкурирует с
линтером, он его измеряет.

**Оговорка.** Числа 96.4% precision и 100% recall получены до гейта О, на корпусе, 18.2% которого
анализатор не разбирал. Они пересчитываются после гейта О и до публикации.

#### П7. Аэродинамическая труба механизмов

**Что.** Проверка экономического механизма до рынка: агенты, враждебные сценарии, утверждение,
зарегистрированное до прогона, вердикт, воспроизводимый по seed.

**Что построено.** Движок, агенты, пять механизмов, 439 собственных тестов зелёные, дисциплина утверждений,
опубликованные отрицательные результаты.

**Чем отличается от остальных.** Два вердикта `refuted` с порогом, названным заранее: кольцо
поручителей в `karman` и гипотеза Q2 в `sting` — 33.0% против порога 80%. Плюс третий: `ton-res`
опроверг продуктовую гипотезу цифрой 0.00%.

**Почему ярус C.** Цикл продажи длинный, покупателей мало, промежуточной метрики нет. Как
доказательство метода — наивысшая ценность; как источник выручки — низшая.

### 4.4. Что продуктом не является

Сырой дата-лейк по цепи. TON-ETL бесплатен и лежит в AWS Public Blockchain Data, Dune стоит поверх
него. Конкурировать на сыром слое не с чем.

Собственный индексатор. Три публичных индексатора расходятся с цепью по значениям на 0.00% —
задача решена, повторять её нечем.

Второй линтер Tolk. Официальный ставится вместе с тулчейном и несёт 39 правил.

## 5. Дорожная карта

### 5.1. Порядок и почему такой

Прежняя редакция ставила публикацию словаря первой, потому что она «занимает вечер и не требует ни
строчки нового кода». Публикация уходит с первого места, и вот почему: артефакт, о котором мы не
можем сказать одной строкой, чем он отличается от каталога фонда на 1 299 опкодов, публикуется не
быстро, а рано. Условие провала «никто не форкнул за 30 дней» меряет чужое поведение, а не наш
артефакт, и потому гейтом не является.

Порядок задан зависимостями: гейт О чинит то, что молча врёт; гейт В сводит пять путей в один;
гейт И описывает, что получилось; продукты выводятся из описи.

### 5.4. Реестр рисков

## 6. Документация

Дисциплина `bohr` — не один гейт, а два, и разделены они по тому, что дисциплина и объём стоят
разного. Дисциплина стоит дёшево и нужна первой: гейты О, В и И пишут свои числа в эти же
документы, и писать их в комплект без правил значит переписывать дважды. Объём стоит дорого и ждёт
описи: переводить по-английски четыре репозитория дороже, чем одну платформу с готовым перечнем
способностей.

**Гейт Д1 — дисциплина.** Комплект документов назван, процедурные файлы удалены в git-историю.
Разделы пронумерованы, перекрёстная ссылка несёт номер раздела. `ARCHITECTURE.md` §1 содержит
нумерованные инварианты, каждый сформулирован запретом. Английский канонический, `docs/ru/` —
зеркало с идентичным деревом заголовков. Каждое число в документе выводится из кода скриптом. Д1
стоит перед гейтом О.

**Гейт Д2 — объём.** Комплект покрывает платформу целиком, включая влитые контуры: `karman` и
`sybil` описаны там же, где `sting`, а не в своих каталогах. Д2 стоит за гейтом И, потому что
описывать способность до того, как она описана в описи, — работа, которую придётся повторить.

**Условие провала обоих:** хотя бы одно число в документации не выводится из кода.

Расхождение уже есть и уже замерено: `docs/README.md` называет 27 крейтов и 853 теста,
`ARCHITECTURE.md` — 29 в одном месте и 26 в другом, фактически 29 и 902. Пока число набирается
руками, оно расходится с кодом — вопрос не «если», а «когда».

## 7. Как измеряется прогресс

| Число | Сейчас | Цель |
|---|---|---|
| Внешних пользователей | 0 | 1 |
| Реализаций доступа к цепи | 2 живых, 2 в закрытом проекте | 1 плюс названное исключение |
| Доля корпуса, разбираемая без ошибок | 100% | 100% |
| Файлов, на которых анализатор молчит, не разобрав | 0 | 0 |
| Команд для полного прогона тестов | 1 | 1 |
| Способностей с воспроизводимой командой | 0 | все |
| Пройденных гейтов | 2 из 5 — Д1, О | 5 |

Строки кода, число крейтов и число тестов прогрессом не являются. Они растут и при движении, и при
его имитации.

## 8. Что сознательно не делается

**Не переписывается `ton-res` на Rust.** Прибор запускается несколько раз в год.

**Не строится свой индексатор.** Расхождение публичных индексаторов с цепью по значениям — 0.00%.

**Не развивается поддержка Tact.** Язык депрецирован, экстрактор заморожен на компиляторе 1.6.13.
Замер шёл перед заморозкой: от 1.5% до 3.3% уникальных хешей кода mainnet
объявляют себя Tact.

**Не пишется второй линтер Tolk.** Официальный несёт 39 правил и ставится вместе с тулчейном.

**Не извлекается общее ядро из `bohr`, `laplace`, `pauli` и `karman`.** Их роднит дисциплина, а не
код.

**Не начинается TVM-отладчик.** Отладчик Tolk вышел вместе с версией 1.4.

**Не объединяются `hepler`, `mary-3`, `stash`, `tribe`.** Отдельные бизнесы с отдельными
покупателями.
