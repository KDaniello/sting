# Гейты

Условия, которым находка обязана удовлетворить, прежде чем уйти в канал приёма. Два уровня:
**официальные**, нарушение которых есть мгновенный отказ программы, и **наши**, нарушение которых
означает отправку шума той команде, куда мы хотим попасть.

Гейт есть проверяемое условие, а не намерение. «Похоже на дефект» гейтом не является.

---

## 1. Официальные гейты — мгновенный отказ при нарушении

Взяты прямо из документации программы и её навыка доказательства. Каждый жёсткий.

| # | Гейт | Что проверить |
|---|---|---|
| O1 | **Находка уровня машины несёт исполняемое доказательство в их форме** | пробник запускается под их ассемблером и показывает эффект |
| O2 | **Только нынешняя версия** | версия записана в записи находки |
| O3 | **Не отладочный опкод и не отладочный сток** | эффект воспроизводится без отладочных флагов |
| O4 | **Реалистичный путь в нормальной сети** | без контроля над хостом, над большинством валидаторов и без утёкших ключей |
| O5 | **Цель в скоупе** | сверено со [`SCOPE.md`](./SCOPE.md) в день отправки |
| O6 | **Не известное поведение** | сверено со [`SCOPE.md`](./SCOPE.md) §4 |
| O7 | **Пробящий узел самоиммунен**, для находок в консенсусе | узел жив до наблюдения эффекта на честных узлах, иначе прогон недействителен |

**O1 — самый частый провал.** Гипотеза уровня машины, доказанная в нашем эмуляторе, официальным
доказательством **не является**: программа требует их формы. Наш биндинг есть префильтр, их пробник —
артефакт. Нужны оба, и именно в таком порядке.

---

## 2. Наши гейты — не отправлять шум

Строже минимума программы. Программа отклонила бы плохой репорт; мы хотим, чтобы каждый репорт
**повышал** доверие.

| # | Гейт | Почему |
|---|---|---|
| S1 | **Гипотеза записана до пробы, с ожидаемым исходом** | подгонка утверждения под увиденное есть самообман; та же нуль-модель, что в методике продукта |
| S2 | **Находка пережила попытку опровержения** | прежде чем поверить: нет ли версии-гейта? не берётся ли газ там, где не заметили? достижим ли путь? |
| S3 | **Каждое число измерено, а не оценено** | газ, память, процессор и номера последовательностей — настоящими средствами; сборка, версия, пробник и код возврата записаны |
| S4 | **Минимальное доказательство, а не максимальный эксплойт** | доказательство на границе, где виден тренд, а не доведение машины до смерти |
| S5 | **Воспроизводится с чистого клона** | прежде чем что-либо назвать готовым к сдаче, оно прогоняется на чистом дереве с одними нужными артефактами |
| S6 | **Запись в журнале есть и полна** | одна находка есть одна запись в [`findings/`](./findings/README.md), включая отрицательный результат |
| S7 | **Один репорт — одна находка** | не пакет сырых гипотез; каждая проходит O1–O7 и S1–S6 отдельно |

## 3. Конвейер находки

Порядок обязателен. Пропущенная ступень означает, что находка не готова, а не почти готова.

```
  гипотеза (S1: записана до пробы, с ожидаемым исходом)
      │
      ├─ грубая проверка скоупа (O5, O6) ── вне скоупа? → журнал, стоп
      │
      ├─ ПРЕФИЛЬТР в нашем эмуляторе ── для находок уровня машины: быстрый скрининг в памяти
      │       │                          гипотеза не подтвердилась? → журнал, отрицательный результат, стоп
      │       ▼
      ├─ доказательство по официальной методике
      │       ├─ машина    → их пробник (O1)
      │       ├─ консенсус → смешанная сеть, самоиммунный узел (O7)
      │       └─ контракт  → локальная тестовая сеть, развёртывание и запуск
      │
      ├─ измерение (S3) плюс сравнение с заряженной базовой линией
      │
      ├─ попытка опровержения (S2) ── опровергнуто? → журнал, отрицательный результат, стоп
      │
      ├─ финальные гейты (O2, O3, O4, S4, S5)
      │
      ├─ чистый прогон с нуля (S5)
      │
      └─ запись полна (S6) → отправка (S7, один репорт)
```

**Отрицательный результат на любой ступени есть результат.** Он идёт в журнал с тем же весом, что и
находка, и цикл останавливается, а не крутит параметры наугад, — это собственное правило официального
чек-листа.

## 4. Находка уровня машины: точная последовательность

Самый частый и самый регламентированный случай. Шаги взяты из официального навыка доказательства.

1. **Заземлить гипотезу в нынешнем коде.** Найти мнемонику и её реализацию: где заряжается газ, где
   аллоцируются ячейки и записи стека, какая версия её гейтит и какой поверхности она принадлежит.
2. **Префильтр в нашем эмуляторе** — прогнать паттерн на настоящем байткоде в памяти и отсеять
   очевидно несостоятельное до того, как трогать их форму.
3. **Минимальный пробник.** Один опкод или крошечная последовательность под лимитом газа.
   Масштабировать **один** параметр за раз.
4. **Измерить ресурсы хоста отдельно от газа самой машины.** Память и процессор настоящими средствами,
   зависания — таймаутом, огромный вывод — в файл. Записать стек, код возврата, газ, пиковую память,
   времена и параметр масштаба.
5. **Сравнить с заряженной базовой линией.** Для ячеек — дешёвое преобразование против оплаченного
   построения; для вложенного прогона — стек, построенный снаружи, против стека, построенного внутри и
   оплаченного.
6. **Классифицировать.** Подтверждать только тогда, когда ограниченное доказательство показывает
   **достижимый в продакшене** путь, где газ машины плоский или сильно ниже памяти, процессора,
   вывода или криптографической работы хоста, **и код объясняет почему**. Понижать, если нужен
   отладочный сток. Отвергать при устойчивых отрицательных фактах: ограниченные длины, ограниченная
   глубина ключей, мемоизированный обход, явно линейный газ, оплаченное движение стека, версия-гейт,
   закрывший исторический фикс.

**Не хардкодить число газа между версиями.** Записываются сборка, версия, точный пробник, код возврата
и измеренный газ.

## 5. Что делает находку **не готовой** — проверка перед отправкой

Быстрый финальный список. Любое «нет» возвращает находку в конвейер, а не выпускает её.

- [ ] Цель в скоупе **сегодня**, документация перечитана?
- [ ] Её нет в списке известных поведений?
- [ ] Для находки уровня машины: есть ли доказательство в их форме, а не только наше воспроизведение?
- [ ] Нынешняя версия?
- [ ] Без отладочных флагов?
- [ ] Достижим ли путь без контроля над хостом, кворумом или ключами?
- [ ] Каждое ли число измерено, записаны ли сборка и версия?
- [ ] Пытались ли гипотезу опровергнуть и пережила ли она это?
- [ ] Воспроизводится ли с чистого клона?
- [ ] Полна ли запись в журнале?
- [ ] Один репорт — одна находка?

Одиннадцать «да» означают, что можно отправлять. Меньше означает, что нельзя.

## 6. Чего этот документ не покрывает

Он не говорит, что искать, — это [`PLAYBOOK.md`](./PLAYBOOK.md), — и не определяет
поведение, что есть [`RULES.md`](./RULES.md). Он определяет условия, при которых нечто может покинуть
этот репозиторий, и каждое из них проверяемо.
