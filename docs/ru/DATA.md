# Данные

Корпуса, вендоренные бинари, внешние API и правила работы с данными цепи. Чем всё это что-то
доказывает — [`TESTING.md`](./TESTING.md).

Остальным управляет один принцип: **у каждого файла корпуса объявлено происхождение.** Каталог без
`SOURCE.md` или `MANIFEST.json` есть дефект, а не временное положение дел. Для тысячи двухсот файлов,
пришедших механическим обходом реестра, написанная руками проза заменена машиночитаемым манифестом —
заменена, а не опущена.

---

## 1. Два корпуса, две задачи

### 1.1 `corpus/` — security

| Каталог | Что в нём | Роль |
|---|---|---|
| `clean/acton-contracts/` | шестнадцать настоящих, независимо задеплоенных контрактов: jetton, NFT, DNS, multisig, elector, config, кошельки, vesting, telemint | основной источник ложных срабатываний |
| `clean/tolk-bench/` | семь проектов эталонного набора фонда | второй независимый источник |
| `clean/converted/` | оригиналы FunC, конвертированные в Tolk | пары для Tier 2 экстрактора и дополнительный материал детекторам |
| `clean/production/` | задеплоенный код протоколов, взятый как есть | настоящие формы, которые никто не писал для нас |
| `clean/synthetic/` | написанные руками проекты под ситуации, которым нет реального примера | там, где у реальности образца не нашлось |
| `fixtures/detectors/` | golden-фикстуры, положительные и отрицательные, по три-пять на детектор | доказывают, что детектор срабатывает на паттерне и молчит без него |
| `fixtures/cross-file/` | многофайловые проекты, которые **реально компилируются** вендоренным компилятором | подтверждают кросс-файловую резолюцию независимо от бенчмарка |
| `fixtures/emulator/`, `fixtures/bridge/`, `fixtures/fuzz/` | ячейки code и data, сценарии моста, вход фаззера | динамический контур |
| `baseline.json` | закоммиченный снимок precision, recall и ложных срабатываний по каждому детектору | регрессионный гейт |

297 файлов Tolk в корпусе: 174 в `clean/` и 123 в `fixtures/`, из которых 104 — golden-фикстуры.
Многофайловые проекты сворачиваются в сорок чистых проектов.

**Два проекта на Tolk не компилируются вовсе.** Они используют собственный генерируемый тулчейном
маппинг путей, который ни JavaScript-, ни нативный компилятор в одиночку не резолвит. Это принятое
ограничение, задокументированное в `SOURCE.md` самого каталога, и проекты **прозрачно исключены** из
корпуса, а не молча пропущены.

**Фикстура, написанная под один детектор, задевает остальные, и это учтено.** Golden-фикстуры `AC` и
`UTA` списаны с настоящего низкоуровневого кода, у которого сигнатура точки входа по построению не
зовёт проверку конца разбора. Ложные срабатывания `LEP` из-за этого выросли на десять — не регресс
`LEP`, а известный побочный эффект состава корпуса. Урок применён сразу: фикстуры `UDA` намеренно
добавили недостающую проверку, чтобы не повторить это, и строки `LEP` и `AC` после появления `UDA`
побайтово те же — проверено диффом `baseline.json`, а не наблюдением, что агрегат не упал.

### 1.2 `corpus-abi/` — слой извлечения

| Каталог | Файлов | Происхождение |
|---|---|---|
| `clean/tact/` | 19 | собственный тестовый набор компилятора Tact, `SOURCE.md` |
| `clean/tact-registry/` | 129 | обход публичного реестра ABI, `MANIFEST.json` |
| `clean/func/` | 1197 | тот же обход плюс собранный руками набор роста, `MANIFEST.json` и `SOURCE.md` |
| `clean/tolk/` | — | Tolk переиспользует `corpus/clean/` напрямую, второй форк не заводится |
| `method-dictionary.json` | 1388 method id в словаре | продукт `dictionary-build` по всем трём корпусам |
| `baseline.json` | Tier 1, Tier 2 и пропускная способность | регрессионный гейт |

**Настоящая ошибка, пойманная до коммита и стоящая записи.** Сто тридцать семь файлов Tact из обхода
реестра сначала легли прямо в `clean/tact/` — тот каталог, который бенчмарк использует как базовую
линию точности Tier 1. Загрязнение калибровочного корпуса материалом, извлечённым тем же
инструментом, сделало бы измерение бессмысленным. Они вынесены в отдельный корень реестра и
подключены вторым независимым источником; живой прогон Tier 1 после фикса подтвердил полную
структурную полноту и отсутствие регрессий.

## 2. Вендоренные внешние бинари

| Каталог | Что | Зачем | Ограничение |
|---|---|---|---|
| `vendor/tolk/` | нативный компилятор Tolk | `abi.json` и `symbolTypes.json` для детекторов и Tolk-экстрактора | **только сборка под Windows** |
| `vendor/tact/` | компилятор Tact и его пакеты | Tact-экстрактор | нужен Node.js; холодный старт стоит секунд |
| `vendor/libemulator/` | эмулятор TVM на C++ | вся динамика: мост, honeypot, проба словаря, фаззинг | под Windows публикуется без импортной библиотеки |
| `vendor/fift/` | Fift | пересборка байткода в крейте реестра | |
| `vendor/tree-sitter-func/` | грамматика FunC | экстрактор Tier 2, разбор в памяти | |
| `vendor/tree-sitter-tolk/` | грамматика Tolk | всякий разбор исходника Tolk | форк от 0.0.5, которая знает Tolk 1.2 |

**Отсутствие сборки компилятора Tolk под Linux — блокирующий продуктовый пробел, а не неудобство**:
главный язык платформы недостижим через главный канал доставки — контейнер сервиса. Он записан
пробелом, и его закрытие есть запланированная работа, а не известная досада.

`libemulator` грузится **динамически**, а не линкуется при сборке, ровно потому, что релиз под
Windows не несёт импортной библиотеки. Ограничение кое-что купило: путь берётся из
`STING_LIBEMULATOR_PATH`, и тест без него **пропускается, а не падает**.

## 3. Внешние API

| Сервис | Кто зовёт | Зачем |
|---|---|---|
| toncenter v3 | `sting-corpus`, `sting-abi-coverage`, `sting-scamcheck` | code и data по адресу, поток транзакций, держатели жетона, коллекции NFT |
| tonapi | `sting-corpus` запасным путём, `sting-scamcheck` | тот же класс данных от второго провайдера |
| хостинг сырых файлов | обход реестра | несколько тысяч исходников одним заходом, на хосте, который не делит лимит с API |
| API биржи | `sting-scamcheck` | выпуск пула ликвидности |

Проект **не держит ноду TON**. Решение перепроверено замером: узкое место сбора — дедупликация по
хешу кода, в шестьдесят-девяносто раз в любом окне, и нода этого не меняет.

---

## 4. Правила работы с внешним API

**Обход создаёт настоящую устойчивую нагрузку на публичный сторонний сервис.** Это не тестовый
эндпоинт и не наш сервер.

- Пилотный размер по умолчанию — пять тысяч. Начинать следует с пилота, а не с полного потока.
- Дедупликация по хешу кода делается **до** фетча: адрес, чей хеш уже известен, не скачивается вовсе.
  Отсюда экономия в шестьдесят-девяносто раз, и она же настоящий ограничитель.
- `Retry-After` соблюдается — отдельным модулем, а не строчкой в клиенте.
- Дисковый кеш обязателен и разделён по сетям: mainnet и testnet — разные поддеревья, поэтому
  переключение сети для того же адреса **никогда** не отдаёт байткод другой сети.
- `--force-refresh` обходит кеш явным решением вызывающего, никогда по умолчанию.

**Дефект ровно этого класса, найденный и исправленный.** Резолюция ячеек-ссылок на библиотеки имела
две настоящие неисправности: она обходила устаревший кеш и не повторяла попытку. Следствие было не
косметическим — **38.6% «нераспознанных» контрактов оказались не пробелом словаря**, а
нерезолвнутыми ячейками библиотек. Один фикс сдвинул картину покрытия дальше, чем месяц пополнения
словаря.

## 5. Данные, которые в репозиторий не попадают никогда

- **Приватный код пользователя.** Инструмент читает файлы там, где запущен, и никуда их не копирует.
- **Результаты прогонов по внешним целям.** Прогоны по десяти проектам GitHub, живому протоколу и
  CTF-полигону дали настоящие фиксы, но сами цели **не вендорятся**: это чужой код, и режим был явно
  внутренним — ничего не сообщалось и не раскрывалось ни одному автору. Честное следствие: эти
  проверки **невоспроизводимы из репозитория**, и это сказано везде, где от них зависит число.
- **Ключи и токены.** Доступу к цепи нужен ключ; он живёт в `.env`, который в игноре, а
  `.env.example` документирует два имени без значений.

## 6. Как воспроизвести замеры

```
cargo run -p sting-cli     -- bench --report bench-report.md          # precision и recall security
cargo run -p sting-abi-cli -- bench --report abi-bench-report.md      # Tier 1, Tier 2, пропускная способность
cargo run -p sting-abi-cli -- dictionary-build                        # пересборка словаря method id
cargo run -p sting-abi-cli -- coverage-report --db coverage.sqlite3   # покрытие mainnet
make numbers                                                          # факты, которые документам позволено называть
```

Первые две сверяются с закоммиченными снимками и падают на регрессе. `--update-baseline`
перезаписывает снимок **по тирам** и не стирает тир, который в этом вызове не запускался, — это был
настоящий дефект, исправлен, и за ним стоят три теста.

---

## 7. Чего этот документ не покрывает

Он не говорит, что доказывает корпус, — это [`TESTING.md`](./TESTING.md), где сказано и то, чего
каждый источник доказать не может. Он не перечисляет корпус файл за файлом: это делают манифесты, и
именно их читает проверка. И он не держит ни одного числа о точности: они живут в двух файлах
снимков, откуда их и читают гейты.
