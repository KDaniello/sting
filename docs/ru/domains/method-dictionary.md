# Словарь method id

Как распознать контракт, исходника которого нет ни у кого. Самый дифференцированный актив проекта и
кандидат на первую публичную победу.

---

## 1. Идея

Get-метод в TON определяется не именем, а **method id** — числом, выведенным из имени по фиксированной
формуле. Формула односторонняя, но конечная: имя в число. Значит, имея достаточно большой список
настоящих имён, можно построить обратный словарь и **проверять наличие** метода на любом байткоде, без
исходника вовсе.

Прямой аналог четырёхбайтового реестра Ethereum. Для TON такого нет ни у кого.

Механика буквально такая:

```
адрес → настоящие code и data из цепи → для каждой записи словаря:
    вызвать её method id через настоящую виртуальную машину → метод есть или нет
```

Ни одной строки исходника не читается, и ничего не угадывается: это настоящий эмулятор на настоящих
байтах.

## 3. Почему обход сети перестал работать, а обход реестра — нет

Прямой вопрос был задан и **проверен, а не предположен**: даст ли больше истории mainnet более быстрое
пополнение словаря?

Ответ отрицательный, и причина структурная. Обходчик и так идёт назад по настоящей истории, так что
«больше истории» не есть новый рычаг. Дедупликация по хешу кода держится в шестьдесят-девяносто раз в
**любом** окне, поэтому продолжение свипа в основном переоткрывает известные коды: **свип по тридцати
тысячам адресов нашёл четыре новых уникальных кода** за долгий прогон.

Настоящий рычаг оказался другим: развязать рост словаря со скоростью сбора вовсе — обойти **весь**
публичный реестр ABI механически, а не проверять реактивно найденные пилотом пробелы.

Проверено эмпирически **до** того, как браться: всё дерево реестра одним запросом — двадцать тысяч
записей, не обрезано, **1348 уникальных верифицированных хешей кода**.

Полный обход прошёл: около 7677 исходных файлов, забранных с хоста сырых файлов, а не через API,
который ограничил бы частоту; отфильтровано до 2016 файлов с меткой get-метода; прогнано через
настоящие экстракторы этого workspace:

| Язык | Успешно из общего | Новых методов |
|---|---|---|
| FunC | 1185 из 1207 | **+874** |
| Tolk | 17 из 100 | компилятор строг к резолюции импортов |
| Tact | 137 из 709 | ещё строже |

**Словарь вырос с 219 до 1388**, в шесть раз. Живая проверка перепробой сдвинула распознавание с
75.2% до **86.2%**, а сходимость подтверждена **тремя последовательными прогонами**, дающими то же
число.

Обход сети остановлен досрочно: обход реестра оказался на порядок продуктивнее на единицу усилий.

**Инженерная цена**: обнаружение проектов было плоским, на один уровень, и расширено до рекурсивного
обхода с регрессионным тестом, доказывающим, что старые плоские метки не меняются.

**Ошибка, пойманная до коммита**: 137 файлов из реестра сначала легли прямо в тот каталог, который
бенчмарк использует базовой линией точности Tier 1. Загрязнение калибровочного корпуса материалом,
извлечённым тем же инструментом, сделало бы измерение бессмысленным. Они вынесены в отдельный корень и
подключены вторым независимым источником; живой прогон после фикса подтвердил полную полноту и
отсутствие регрессий.

**Прослеживаемость** для тысячи двухсот файлов есть не написанная руками проза, а машиночитаемый
манифест в каждом новом каталоге: хеш кода, верификатор, исходный путь, извлечённые методы. Методика
лежит рядом.

## 4. Два настоящих дефекта резолюции ячеек-ссылок

Крупнейшая одиночная находка всего направления, и она была **не** про словарь.

**38.6% «нераспознанных» контрактов оказались не пробелом словаря**, а нерезолвнутыми
ячейками-ссылками на библиотеки: ячейка указывает на код, хранимый в сети отдельно, и пока она не
разрезолвлена, байткод выглядит нераспознаваемым.

Два дефекта в самой резолюции: она обходила устаревший кеш и не повторяла попытку. Один фикс сдвинул
картину покрытия дальше, чем месяц пополнения словаря.

**Урок, записанный явно**: прежде чем объяснять низкое покрытие нехваткой данных, надо проверить, что
измеряется то, чем кажется. Тот же класс ошибки, что проверка precompiled-контрактов по неверному логу
([`emulator.md`](./emulator.md) §8).

## 5. Перепроба появилась по факту пробела, а не по дизайну

Настоящий пробел: словарь, выросший **после** первой пробы кода, шанса на этот код не получал, потому
что уже пробованный код повторно не рассматривался. То есть отдельная пересборка словаря могла удвоить
его, не сдвинув ни одной цифры покрытия.

Перепроба перепроверяет ранее нераспознанные коды и не трогает распознанные.

## 6. Хранилище обхода

База SQLite держит адреса, хеши кода, исходы проб и позицию обхода для возобновления.

Дедупликация происходит **до** фетча: адрес, чей хеш кода уже известен, не скачивается вовсе. Отсюда
экономия в шестьдесят-девяносто раз, и она же настоящий предел скорости, а не пропускная способность
API.

Отчёт о покрытии печатает агрегатное покрытие плюс лучших кандидатов на расширение словаря — код,
нераспознанный на многих разных адресах, с сортировкой по их числу. Это и есть рабочий цикл: отчёт
называет пробелы, пересборка их закрывает, перепроба меряет эффект.

## 7. Оставшаяся доля

Разобрана, а не списана:

- **Многофайловая инфраструктура обмена сообщениями** — структура слишком сложная для сегодняшнего
  однофайлового эвристического экстрактора. Крупнейший из трёх кусков.
- **Распознанный проект без компилируемого исходника** — исходник существует и в изоляции не
  собирается.
- **Единично встреченные контракты** — длинный хвост, где извлекать нечего.

Источник роста, который работал, **исчерпан**: реестр обойден целиком. Три гипотезы дальнейшего роста
и их цена — [`OPEN-QUESTIONS.md`](../OPEN-QUESTIONS.md) §4. Самая дешёвая проверка — доля хвоста, чьего
исходника нет **нигде**, — не сделана.

## 8. Какой компилятор написал цепь

Периметр языков есть решение, а решение без замера есть предпочтение. Одна команда считает Tact по
тем же уникальным хешам кода, что и §2:

```sh
abi-layer tact-share --db coverage-data/pilot.sqlite3
```

| Вердикт | Кодов | Читается как |
|---|---|---|
| объявляет себя Tact | 6 | два маркера компилятора или три |
| один маркер | 7 | один маркер не разрешается догадкой |
| ни одного маркера | 376 | сюда же ложится Tact, собранный с умолчаниями |
| нет ячейки данных | 2 | первый встреченный адрес более не разрешается, и проба не бежала |

**От 1.5% до 3.3% из 389 опробованных уникальных хешей кода объявляют себя Tact.** Полоса есть
неоднозначность одиночного маркера, а не погрешность замера.

Маркеры — `supported_interfaces`, `get_abi_ipfs` и `lazy_deployment_completed`. Два вместе суть
отпечаток компилятора, один — нет, и корпус говорит почему: из 46 файлов с
`supported_interfaces` 2 суть рукописный FunC, среди них `whales-nominator-pool-get.fc`.

Маркер считается присутствующим, когда вызов возвращается чисто, и отсутствующим при любом ином
коде выхода. Правило строже, чем у словарной пробы, и три маркера — причина: каждый возвращает
константы и не читает хранилища, то есть на контракте, выданном Tact, ни один из них упасть
не может. Более слабое правило пробовалось первым и оказалось негодным: 324 кода из 389 отвечают
промахом таблицы диспетчеризации, 56 — собственным `THROWIF 32` кошелька после сравнения
идентификатора с `seqno` и `get_public_key`, и счёт этих 56 как неясных превращал верхний конец 3.3%
в 18.3%.

**Пол замерен, потолок этим способом не замерить.** Tact 1.4.1 (2024-07-26) сделал
`supported_interfaces` и `get_abi_ipfs` опциями проекта, а 1.6.0 (2025-02-28) перестал выдавать
`lazy_deployment_completed` по умолчанию. Контракт, собранный с тех пор с умолчаниями, не несёт
маркера и считается в тех 376. Другого отпечатка Tact байткод не оставляет, и ограничение сверху
требует исходника, а не пробы.

**Заморозка стоит на обеих половинах.** `sting-abi-tact` остаётся на компиляторе 1.6.13 — той
версии, чья собственная установка печатает уведомление о депрецировании с указанием на Tolk, и это
аргумент, не зависящий ни от какой доли. Замер говорит, что объявленная популяция мала, а не
предполагается таковой. Тесты идут, экстрактор не развивается. FunC остаётся по обратной причине:
он легаси как язык, а не как цепь.

Числа записаны в [`benches/baseline.toml`](../../../benches/baseline.toml) вместе с командой, их
получившей.

**Чего замер не говорит.** Он не даёт долю Tact среди адресов: дедупликация идёт в шестьдесят —
девяносто раз, и распределение по адресам есть другое число. Он не называет версию Tact. Он не
разделяет FunC и Tolk, ибо отпечатка не оставляет ни тот, ни другой.

## 9. Почему это кандидат на первую публичную победу

Три свойства, которых у остальных частей проекта нет:

- **Артефакт готов и измерен.** Словарь есть файл, пересобираемый одной командой, с машиночитаемым
  происхождением у каждой записи.
- **Ему не нужна инфраструктура.** Датасет не надо хостить, мониторить и держать в аптайме, в отличие
  от HTTP-сервиса.
- **Ниша не занята никем.** Аналог в Ethereum есть базовая инфраструктура, на которую опираются
  эксплореры и кошельки. У TON такого нет.

Не хватает единственного: места, куда положить.

**Оговорка, обязательная к публикации вместе с данными**: 86.2% есть доля **уникальных хешей кода**,
встреченных одним обходом на одну дату, а не доля контрактов сети и не доля адресов. Дедупликация в
шестьдесят-девяносто раз означает, что распределение по адресам другое, и подача одного числа как
другого была бы подменой.

## 10. Что датасет говорит о себе и что подтверждает сказанное

Файл, покидающий этот репозиторий, отвечает на три вопроса, которые его читателю задать некому:
откуда данные, что с ними можно делать и тот ли это файл, который даёт данный корпус. До этой вехи он
не отвечал ни на один.

| Поле | Значение |
|---|---|
| `schema_version` | `1.1` |
| `licence` | `CC0-1.0` |
| `built_by` | `abi-layer dictionary-build` |
| `sources` | шесть корпусов, у каждого свой `SOURCE.md` |
| записей без происхождения | 0 из 1 433 |

Происхождение записано дважды, ибо один его уровень сам по себе бесполезен. Каждая запись называет
контракты, в которых имя встретилось; каждый корпус называет, откуда взялись его контракты. «Встречено
в `counter/Counter.tolk`» ничего не говорит читателю, у которого нет этой рабочей копии, а корпус без
собственного `SOURCE.md` теперь роняет сборку, вместо того чтобы дать датасет, ссылающийся в никуда.

**Пересборка и есть проверка.** `abi-layer dictionary-verify` пересобирает словарь во временный файл и
сравнивает байт в байт: 706 060 байт воспроизведены. Ради этого артефакт пришлось упорядочить —
хеш-таблица сериализуется в том порядке, в каком обходится, и две сборки одного корпуса давали два
файла, значащих одно и то же и различающихся так, что различие никто не мог прочесть. Упорядочивание
теперь происходит внутри записи, а не отдельным шагом, который вызывающий обязан помнить.

**Аудит — вторая проверка, и вопрос у неё другой.** Пересборка говорит, что файл — это то, что даёт
корпус; она молчит о том, говорит ли корпус до сих пор то, что заявляет файл. `abi-layer
dictionary-audit` перекомпилирует выборку и сверяет её с собственным `abi.json` компилятора tolk,
прочитанным из его артефакта, а не через экстрактор, собравший словарь: **100 из 115 утверждений,
полученных от компилятора, по 40 контрактам, расхождение 0.0%** при пороге 1%. Сдвинутый вручную id
даёт 5.0% и ненулевой код возврата.

Об записях Tact и `FunC` он не говорит ничего, а это большая часть датасета. Их id выведены той же
односторонней формулой, и артефакта компилятора, с которым их сверить, нет.

## 11. Различие с каталогом фонда

`ton-blockchain/abis` — рукописный каталог описанных контрактов. Этот датасет — машинный обход того,
что развёрнуто. Кто что несёт, оставалось утверждением, пока не было посчитано, а утверждение такого
рода льстит тому, кто его делает: вслух называют только одну сторону.

Названы обе. Против коммита `90c4c6b`, прочитанного 2026-08-23:

| Замер | Значение |
|---|---|
| их имён get-методов, по 285 файлам типов | 600 |
| наших | 1 405 |
| в обоих | 283 |
| только здесь | 1 122 |
| только там | **317** |
| доля их каталога, которую несёт этот датасет | **47.2%** |
| доля этого датасета, которую несёт их каталог | 20.1% |

317 — то самое нелестное число, и читать стоит с него: рукописный каталог описывает контракты, до
которых обход развёрнутого кода не достаёт, и никакой обход его не заменит.

749 их файлов с тестами и вспомогательным кодом из этих 600 исключены намеренно. Их тестовые случаи
написаны как get-методы, и учёт таких имён приписал бы каталогу имена, на которые не отвечает ни один
контракт в цепи, — раздувать сторону, с которой себя сравнивают, так же нечестно, как её занижать.

Опкоды названы, но не сравниваются: их каталог объявляет 1 296 штук, а опкоды, известные этому дереву,
— стандартные, они в `sting-tep`, а не в выученном датасете.

`abi-layer catalogue-fetch` пересобирает два их списка из клона, читая коммит из самой рабочей копии, а
не принимая его на веру, и беря дату чтения из аргумента, а не из часов, — одна и та же копия даёт те
же байты. Списки закреплены как фикстура, ибо сравнение, вход которого может измениться под ним, — это
сравнение, которое никто не воспроизведёт.

**Где датасет будет жить, всё ещё открыто**, и это [`DECISIONS.md`](../DECISIONS.md) §8, а не
недосмотр: публикация — единственный шаг, который нельзя отменить.

## 12. Чего этот документ не покрывает

Он не описывает, как схема извлекается из исходника, — это [`extractors.md`](./extractors.md), — и не
описывает эмулятор, который зовёт, что есть [`emulator.md`](./emulator.md). Он описывает одну
способность, числа, говорящие, как далеко она достаёт, и то, чего не покрывает даваемый ею датасет.
